# ERR-04: Diagnostic withdrawal

| | |
| --- | --- |
| Epic | [Errors, diagnostics and recovery](../../README.md#err--errors-diagnostics-and-recovery) |
| Phase | Phase 1 — Layers |
| Status | Done |

## Summary

Diagnostics raised on paths that are later abandoned must disappear, so every error is reported once.

## Scope

- Every diagnostic records the layer and the step that raised it.
- Marks record their own layer's diagnostic count. Rewinding a mark withdraws the diagnostics its own layer raised after it, never another layer's ([ADR-0030](../../docs/decisions/0030-rewinds-recovery-restarts-and-reuse-keep-all-parse-state.md) point 4).
- Marks save the diagnostic count only in a grammar lowered on its own that contains `Recover`, `OrInsert`, `Embed` or `Bind`; a parser that a `Bind` continuation returns decides for itself. In such a grammar, in a run with a failure log, a successful `Longest` with more than one alternative runs its winner again, after putting back the failure record it started with ([ADR-0030](../../docs/decisions/0030-rewinds-recovery-restarts-and-reuse-keep-all-parse-state.md) points 6 and 9; [ADR-0031](../../docs/decisions/0031-constructs-that-read-their-input-back-pin-their-start.md) point 6; [ADR-0033](../../docs/decisions/0033-a-longest-reruns-its-winner-on-the-saved-failure-record-and-each-root-chooses-its-marks.md)).
- A hook for mode invalidation and restarts to withdraw the diagnostics raised by steps that are run again or whose outputs are discarded (used by MODE-02 and STRM-02).
- A withdrawn diagnostic that was built from the furthest failure gives that failure back, before the rewind undoes mode changes ([ADR-0030](../../docs/decisions/0030-rewinds-recovery-restarts-and-reuse-keep-all-parse-state.md) point 8).

## Acceptance criteria

- [x] Property test: no diagnostic survives from an abandoned alternative.

## Outcome

Delivered diagnostic withdrawal under [ADR-0030](../../docs/decisions/0030-rewinds-recovery-restarts-and-reuse-keep-all-parse-state.md) points 4, 6, 8 and 9 and [ADR-0031](../../docs/decisions/0031-constructs-that-read-their-input-back-pin-their-start.md) point 6, as refined by [ADR-0033](../../docs/decisions/0033-a-longest-reruns-its-winner-on-the-saved-failure-record-and-each-root-chooses-its-marks.md). Each layer's failure log holds that layer's diagnostics. A mark that goes back withdraws the ones raised since it was taken, and a withdrawn diagnostic built from the furthest failure gives that failure back. Grammars that cannot raise diagnostics keep two-field marks.

Deviations and decisions:

- [ADR-0033](../../docs/decisions/0033-a-longest-reruns-its-winner-on-the-saved-failure-record-and-each-root-chooses-its-marks.md) refines ADR-0030 point 6: a `Longest` puts back its saved failure record before running its winner again, and where the grammar can raise diagnostics, a run with a failure log runs the winner again whenever there are several alternatives. ADR-0030's rule let a winner's diagnostic report a loser's failure.
- ADR-0033 refines ADR-0030 point 9: marks are chosen for each grammar lowered on its own, so a parser that a `Bind` continuation returns decides for itself.
- A diagnostic records its step as the step's start position. Its layer is the log that holds it, and `ToDiagnostics` names the layer on each error.
