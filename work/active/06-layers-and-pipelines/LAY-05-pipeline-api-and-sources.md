## Summary

Chain layers into a parser and run it over in-memory or reader input.

## Scope

- `Pipeline.From(layer).Then(...)`.
- `Parse(text, source:)` and lazy `ParseMany` returning `IEnumerable<ParseResult<T>>`. The parser is part of the pipeline: `Parse` runs it once, and `ParseMany` runs it until no input remains. A failed item is the last result, and an item that consumes nothing throws `GrammarException` until ANA-03 ([ADR-0038](../../docs/decisions/0038-pipelines-end-in-a-parser-run-again-whole-and-name-sources-without-a-registry.md) points 1 and 2).
- `TextReader` sources with blocking pulls. Each character gets the root-layer span (§ Span rules, rule 1): character *i* has \[*i*, *i* + 1).
- Each root source's upstream reports `InputStart` and `InputEnd`, the zero-width spans where its source starts and ends: 0 and the text's length in memory, and the number of characters read once a reader ends. Every layer above takes them, and `LeadingTrivia` reads them for the trivia before the first item and at the end ([ADR-0036](../../docs/decisions/0036-trivia-is-the-source-between-items-read-with-a-zero-width-parser.md) point 5, [SPAN-05](../05-source-spans/SPAN-05-trivia-attach-mode.md)).
- Slices follow [ADR-0013](../../docs/decisions/0013-slices-view-in-memory-input-and-copy-streamed-input.md): `Parse(text)` builds its root cursor over the caller's memory, so slices are views; over a `TextReader` they are copies.
- Immutable, thread-shareable pipelines; each call owns its buffers and state.
- Remove `SourceRegistry`, which had no producer and held a second copy of each source's name ([Phase 0 review](../../docs/research/2026-10-25-phase-0-review.md) finding 25). Pipelines name their source with `source:` and use `SourceId.Unnamed`. `SourceText`'s public constructors take the text, as a `string` or `ReadOnlyMemory<char>`, and an optional name; those that take an id become internal ([ADR-0038](../../docs/decisions/0038-pipelines-end-in-a-parser-run-again-whole-and-name-sources-without-a-registry.md) point 6).
- A pipeline's result holds its root source text, as [INT-08](../03-interpreter/INT-08-single-layer-parse-api.md)'s does, so Example A's `result.Diagnostics.Render()` shows the full format ([ADR-0024](../../docs/decisions/0024-a-parses-diagnostics-hold-their-source-text.md) points 1 and 5).
- A pipeline over in-memory input runs without failure logs and, when it fails, runs again whole with them ([ADR-0027](../../docs/decisions/0027-in-memory-parses-run-without-a-failure-log-and-again-with-one-on-failure.md)). The second run opens every layer again in fresh buffers, so no item, span hold or state carries over from the first. `ParseMany` records as it goes over every source ([ADR-0038](../../docs/decisions/0038-pipelines-end-in-a-parser-run-again-whole-and-name-sources-without-a-registry.md) point 3).
- `Position` over a streamed input with no items gives offset 0 in `SourceId.Unnamed`, because the buffer has no span to take a source from ([ADR-0035](../../docs/decisions/0035-span-combinators-commit-like-sequences-and-hold-their-spans.md) point 4). That is right, because every pipeline's root is `Unnamed` ([ADR-0038](../../docs/decisions/0038-pipelines-end-in-a-parser-run-again-whole-and-name-sources-without-a-registry.md) point 6).
- When a parse ends, return the segments its stream buffers still hold to the pool. `StreamBuffer<T>.Release` keeps the segment below its horizon, so every finished buffer holds at least one: about 34 KB for characters with the default 1,024-item segment, most of it the 32-byte slots ([LAY-01](LAY-01-streambuffer-and-pulling-cursor.md) review, [SPAN-02](../05-source-spans/SPAN-02-out-of-band-span-storage.md)).
- Over streamed input, make sure `Parse`'s fallback errors read nothing the buffer may have released: `NothingRecorded` reads position 0, and `DepthError` the depth limit's position.
- Under `ParseMany`, each item starts with no furthest failure ([ADR-0030](../../docs/decisions/0030-rewinds-recovery-restarts-and-reuse-keep-all-parse-state.md) point 7). Its result holds the parser's diagnostics raised while parsing it, and a lower layer's from the steps it reads. A diagnostic raised in lookahead past its end waits for the next item, and any left at the end of input go in a last `Failed` result ([ADR-0038](../../docs/decisions/0038-pipelines-end-in-a-parser-run-again-whole-and-name-sources-without-a-registry.md) point 4). Nothing raises a layer diagnostic until ERR-05, ERR-07 or SPAN-07, and no result holds one yet, so results here are `Parsed` or `Failed` with one error, as single-layer `Parse`'s are. The first card that puts layer diagnostics in results builds this rule and tests it ([ERR-07](../04-errors-and-recovery/ERR-07-lexer-recovery-and-cascade-suppression.md)).
- A layer whose step fails throws the internal `LayerFailedException`, which carries that layer's error, named for the layer, with spans in the source. `Parse` catches it and returns `Failed` with that error. `Layer.Open` takes `recordFailures`; LAY-03's tests always pass true. Pass false in a first run over in-memory input, and true when it runs again or under `ParseMany` ([LAY-03](LAY-03-layer-abstraction-and-emit.md) Outcome). Under `ParseMany`, the item running when a layer fails, or the next item if the driver was looking for it, is `Failed` with that error and is the last result ([ADR-0038](../../docs/decisions/0038-pipelines-end-in-a-parser-run-again-whole-and-name-sources-without-a-registry.md) point 3).
- [ADR-0030](../../docs/decisions/0030-rewinds-recovery-restarts-and-reuse-keep-all-parse-state.md) point 4's example through a pipeline, that a parser's mark never withdraws a diagnostic its lexer raised, moved to [ERR-07](../04-errors-and-recovery/ERR-07-lexer-recovery-and-cascade-suppression.md): it needs a layer that raises diagnostics and a result that holds them. ERR-04 holds it by giving each layer its own failure log, without a test ([ERR-04](../04-errors-and-recovery/ERR-04-diagnostic-withdrawal.md) Outcome).
- `Parse` and `ParseMany` over `ReadOnlyMemory<byte>` for pipelines from bytes. When the first layer is `Layer.Utf8()` ([SPAN-06](../05-source-spans/SPAN-06-byte-sources-and-the-decoding-layer.md)), a failed or recovered result holds the text `Encoding.UTF8` decodes after any leading byte-order mark, named by `source:` and decoded once per call. Other byte pipelines hold no text ([ADR-0038](../../docs/decisions/0038-pipelines-end-in-a-parser-run-again-whole-and-name-sources-without-a-registry.md) point 5).

## Outcome

- **Decision:** [ADR-0038](../../docs/decisions/0038-pipelines-end-in-a-parser-run-again-whole-and-name-sources-without-a-registry.md) settled the card's open questions before the build: the parser ends the pipeline, the second run uses fresh buffers, `ParseMany` records as it goes, diagnostics go to the item that reads the step that raised them, bytes in memory get `Parse`, and `SourceRegistry` goes.
- **Pipelines**, in [Pipeline.cs](../../../src/Creole/Pipeline.cs), [PipelineOfTInTOut.cs](../../../src/Creole/PipelineOfTInTOut.cs), [LayeredPipeline.cs](../../../src/Creole/LayeredPipeline.cs) and [LayerOfTInTOut.cs](../../../src/Creole/LayerOfTInTOut.cs):
  - `Pipeline.From(layer)` returns the layer, and `Layer<TIn, TOut>.Then(parser)` makes the public abstract `Pipeline<TIn, TOut>`, backed by the internal `LayeredPipeline<TIn, TItem, TOut>`. Pipelines are immutable; each run owns its buffers.
  - `Parse` and `ParseMany` are extension members in `Pipeline`: over a `string`, `ReadOnlyMemory<char>` or `TextReader` on a `Pipeline<char, TOut>`, and over `ReadOnlyMemory<byte>` on a `Pipeline<byte, TOut>`.
- **Roots.** [MemorySource.cs](../../../src/Creole/MemorySource.cs) reads the caller's memory as one segment that is never released, so `Cursor.Since` returns views over it (ADR-0013). [ReaderUpstream.cs](../../../src/Creole/ReaderUpstream.cs) reads a `TextReader` one chunk per step, blocking, and leaves it open. Both give character or byte *i* the span \[*i*, *i* + 1) and report `InputStart` and `InputEnd`. Layers now read any `ICursorSource<TIn>`.
- **Runs and failures:**
  - `Parse` over memory runs without logs, and on failure, a layer failure or the depth limit runs the whole pipeline again in fresh buffers with every layer recording (ADR-0027, ADR-0038 point 3). `Parse` over a reader and every `ParseMany` record as they go.
  - `LayerFailedException` becomes `Failed` with that layer's error. Fallback errors point at the parser cursor, which the buffer still holds.
  - `ParseMany` is lazy. Each item starts with no furthest failure in any layer, through `FailureLog.ForgetFailure` and a `ForgetFailures` call passed down buffers and upstreams, which STRM-02's restart can reuse. A failed item, or a layer failure while the next item is looked for, is the last result; an item that consumes nothing throws `GrammarException`.
- **Results** hold their root text: the input over memory, and over bytes the text `Encoding.UTF8` decodes after any byte-order mark, built only when a failed result needs it and only when the first layer is `Layer.Utf8()`. Results over a reader hold none until STRM-03. `Diagnostics.Of` builds a one-error collection with or without a text.
- **Memory.** `StreamBuffer<T>` and every layer upstream are disposable, so the buffer a run creates returns its segments to the pool and disposes each buffer below it, however the run ends. The interfaces give a no-op default.
- **Sources.** `SourceRegistry` is removed. `SourceText`'s public constructors take a `string` or `ReadOnlyMemory<char>` and a name; the one that takes an id is internal.
- **Calls made in the build plan**, none of which changes the whitepaper's design:
  - `Pipeline.From` returns the layer, so `lexer.Then(parser)` also builds a pipeline.
  - The `TextReader` overloads take no `source:` until STRM-03 gives the name a use.
  - A grammar that is not valid throws when a `ParseMany` enumeration starts; arguments are checked at the call.
- **Moved to other cards**, recorded in their scope: putting layer diagnostics in results, ADR-0038 point 4's per-item rule, and ADR-0030 point 4's pipeline test go to [ERR-07](../04-errors-and-recovery/ERR-07-lexer-recovery-and-cascade-suppression.md), or to [ERR-05](../04-errors-and-recovery/ERR-05-recover-combinator-and-strategies.md) or [SPAN-07](../05-source-spans/SPAN-07-embedded-languages.md) if either lets a layer raise a diagnostic first. Until then, results are `Parsed` or `Failed` with one error, as single-layer `Parse`'s are. `source:` on reader overloads goes to [STRM-03](../08-streaming/STRM-03-streaming-diagnostics.md).
- **Source compatibility.** A bare `null` is now ambiguous in `new SourceText(null)` and in `layer.Then(null)`, between the new overloads.
- **Tests** (54 new):
  - [PipelineTests.cs](../../../tests/Creole.Tests/PipelineTests.cs) (25): errors from layers and the parser, depth in each, views and copies, threads, disposal however a run ends, and readers, including a depth error 3,000 tokens into a reader, trivia at the end of a reader, and `Position` over a reader with no items.
  - [ParseManyTests.cs](../../../tests/Creole.Tests/ParseManyTests.cs) (17): laziness, failed and layer-failed last results, each item's fresh failure record in the parser and in a lexer, readers against text, early disposal.
  - [ByteSourceDiagnosticsTests.cs](../../../tests/Creole.Tests/ByteSourceDiagnosticsTests.cs) (7 new): SPAN-06's three hand-worked sources through `Parse`, success, `ParseMany` over bytes, bytes without a byte-order mark, and pipelines that hold no text.
  - [WorkedExampleATests.cs](../../../tests/Creole.Tests/WorkedExampleATests.cs) (3 new), [StreamBufferTests.cs](../../../tests/Creole.Tests/StreamBufferTests.cs) (2 new), and every new overload in [ParseResultTests.cs](../../../tests/Creole.Tests/ParseResultTests.cs)' never-default guard.
  - Mutation sweeps in increments 3 to 5: twenty mutations, each failed at least one test.
