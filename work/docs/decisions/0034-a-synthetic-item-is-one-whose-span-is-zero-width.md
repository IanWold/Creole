## Context

§ Span rules rule 3 says a synthetic item "gets a zero-width span at the start of the next input item and is flagged `IsSynthetic`". SPAN-03's scope says the same: an "`IsSynthetic` flag, which downstream layers read". ADR-0032 point 11 gave LAY-03 the spans and left SPAN-03 the flag. Nothing says where the flag is stored, how anything reads it, or which items carry it past the layer that made them.

What exists after LAY-03:

- `Emitted<T>.IsSynthetic` is a step's mark on one output. `TransduceLayer` reads it to place the output's span ([TransduceLayer.cs](../../../src/Creole/Layers/TransduceLayer.cs)), then drops it. `StreamSlot` has no flag, and `SourceSpan` has none.
- Nothing in the engine would read a flag. An error's span is the span of the item at its position, and the renderer takes the line from `CharStart` ([DiagnosticRenderer.cs](../../../src/Creole/Errors/DiagnosticRenderer.cs)). So an error at a DEDENT already shows on the dedented line.
- Grammar authors see no item's span until SPAN-04 adds `Spanned` and `WithSpan`. `Layer.Where` and `Layer.Select` see only items.

The span rules already make every synthetic item zero-width, and make every item that covers source text wider than zero:

| Item | Span | Width |
| --- | --- | --- |
| Root character | \[*i*, *i* + 1) (rule 1) | 1 |
| Derived item or output (rule 2) | From the start of the first input item consumed to the end of the last | Zero only if every item consumed is zero-width at one position |
| Synthetic output, or output of `atEnd` (rule 3) | At the start of the next input item, or the end of the input | Zero |
| Output of `Where` or `Select` | The input item's span | Unchanged |

Two cases make a stored flag and the span disagree, whatever rule carries the flag forward:

- **Synthetic items at two positions.** LAY-03's stateless pass turns each newline into a synthetic `;`. On `a\n\nb`, the two `;` items sit at 1 and 2. A token built from both spans \[1, 2), which covers the first newline. It was built only from synthetic items, yet it covers source text.
- **Derived from synthetic input.** A `Transduce` step that consumes only a DEDENT and emits a derived `BlockEnd` gives it the DEDENT's zero-width span. The step marked it derived, yet it covers no source text.

Separately, SPAN-03's only criterion is Example B's "expected statement" error after a block. Example B's indentation pass keeps a stack, so it needs LAY-04's layer state. LAY-04 is not a blocker of SPAN-03. LAY-07 builds that pass ([ADR-0032](0032-emit-is-a-list-of-outputs-each-derived-or-synthetic.md) point 10), already scopes "Check DEDENT span placement in error messages", and is blocked by SPAN-03.

So these tools store a flag for one narrower thing: an item that error recovery invented. Layout tokens and end-of-file tokens are zero-width without it. Creole's "synthetic" covers layout items and inserted items alike, under any option below.

## Options

### How a reader tells a synthetic item

#### A. A stored flag per item (the whitepaper's position)

Each buffer slot stores a `bool`. `Where` and `Select` copy it, and `Tokens` and `Transduce` set it on derived items by some rule. A public member exposes it, such as `Spanned<T>.IsSynthetic` from SPAN-04, or `SourceSpan.IsSynthetic`.

- Pros: rule 3 as written. The flag could later carry meaning a span cannot.
- Cons: nothing reads it. It needs a rule for derived items, and either rule above disagrees with the span in one of the two cases, so there are two answers to one question. On `SourceSpan` it would be wrong for spans that are not items: an error at the end of the input is zero-width and is not synthetic. On `Spanned<T>` it needs a rule for values built from many items. By layout arithmetic it costs no memory: a packed slot's fields take 28 bytes and are padded to 32, so a `bool` fits (not measured). But every layer must write and carry it.

#### B. Zero width is the definition (recommended)

An item is synthetic exactly when its span is zero-width, which is when it covers no source text. Nothing is stored, and no new member is added.

- Pros: one source of truth, with nothing to keep in step. Every layer carries it already, because every layer carries spans. When an item's span is placed again, as when a mode cascade produces a synthetic output again with a new start (MODE-04), its synthetic status follows. It matches what `SourceSpan`'s documentation already says: a zero-width span "marks a position, such as where an inserted item belongs". Python's tokenizer stores no flag either, though its INDENT spans the indentation where Creole's is zero-width.
- Cons: it redefines both cases above by the span. The token over two `;` items is not synthetic, and the derived `BlockEnd` is. A reader needs the item's span to tell, which grammars get only through SPAN-04. A `Layer.Where` predicate sees only the item, so it must test the item's kind. It cannot tell a recovery-inserted item from a layout item, which Roslyn and tree-sitter can. Option A as written cannot either.

#### C. Defer

Keep rule 3's promise of a flag, and build it when its first reader needs one: SPAN-04, ERR-06 or incremental parsing.

- Pros: no work now.
- Cons: the whitepaper keeps promising a flag that nothing reads. The rule for derived items stays open. SPAN-03 has nothing to build.

### Where the Example B check lives

- **Move it to LAY-07 (recommended).** LAY-07 builds Example B and already scopes the check, so the criterion goes there. SPAN-03 gets a criterion it can meet now with a stateless pass.
- **Block SPAN-03 on LAY-04.** Keep the criterion here, and build Example B's pass once LAY-04 exists, for LAY-07 to reuse. This delays nothing on the Phase 1 gate, since LAY-07 needs LAY-04 anyway.
- **A test-only indentation pass** that keeps its stack in a mutable closure. It works now. But it contradicts the immutable layer state of § B, and it duplicates LAY-07.

## Decision

Option B, and the Example B check moves to LAY-07. The maintainer chose both forks on 2026-11-24.

1. **Definition.** An item is synthetic exactly when its span is zero-width: `Start` equals `End`, in root units. The span rules make this the same as covering no source text: root characters are one wide, and derived spans run from the first item consumed to the last.
2. **Nothing stored.** No slot, span or item carries a synthetic flag. `Emitted<T>.IsSynthetic` stays as it is: a step's mark that places the output's span (ADR-0032 points 7 and 8).
3. **Reading.** A reader tests the span: `span.Length == 0`. Grammars reach an item's span through SPAN-04's `Spanned` and `WithSpan`. No new member is added.
4. **Carried by spans.** `Where` and `Select` keep each item's span, so they keep its status. A derived item is synthetic when every item it consumed is zero-width at one position. It is not synthetic when it covers source text between synthetic items, as the token over two `;` items does.
5. **Values.** A parser value is zero-width when it consumed no source text. `OrInsert`'s token is synthetic in this sense: its span is zero-width. ERR-06 adds nothing more.
6. **Positive width for real input.** Every layer gives an item that covers source text a span wider than zero. SPAN-06's decoding layer and SPAN-07's source maps must keep this when they map decoded characters back to bytes or raw text.
7. **Example B.** LAY-07 takes the criterion "Example B's 'expected statement' error after a block points at the dedented line". SPAN-03's criterion becomes one it can meet now: tests show an item's span is zero-width exactly when it covers no source text, through `Tokens`, `Transduce`, `Where`, `Select` and `Then`. An error at a synthetic output placed after a newline renders on the line of the next token.

Deciding reason: rule 3 already gives every synthetic item a zero-width span, and every other item covers source text. A stored flag would hold the same fact a second time, needs a rule for derived items, and disagrees with the span on two cases. Nothing in the engine reads it.

What would change this:

- A reader that must tell an item error recovery invented from a layout item, as Roslyn's `IsMissing` and tree-sitter's `ts_node_is_missing` do. ERR-06 or editor tooling may need that. It is a narrower notion than synthetic, cannot be read from width, and would be stored, as both tools store it.
- A layer that must give an item covering source text a zero-width span, or the reverse. That would break point 6. SPAN-06 and SPAN-07 are where it could happen.

## Consequences

- **Easier.** SPAN-03 builds no storage and no API. Synthetic status survives every layer, restart and re-placement, because spans do.
- **Harder.** Readers need a span, so a `Layer.Where` that drops synthetic items tests the item's kind instead. The two cases in § Context are settled by the span, which a grammar author may not expect. The docs must say so.
- **Ruled out.** A stored `IsSynthetic` flag on buffer slots, items, `SourceSpan` or `Spanned<T>`.
- **Watch.** SPAN-03's tests pin the equivalence for each layer kind and both cases. SPAN-06 and SPAN-07 test that real input never gets a zero-width span.
