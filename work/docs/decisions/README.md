Note: [ADR-0004](0004-expression-build-operator-table-and-semantics.md) point 5 states the earlier `Named` rule, "only for empty failures". [ADR-0008](0008-control-node-semantics.md) point 4, which stands under [ADR-0011](0011-a-cut-is-dropped-with-every-failed-attempt.md), extends it to empty successes for every node, expressions included.

Note: [ADR-0015](0015-a-prefix-operand-takes-only-tighter-levels.md) refines two more points of ADR-0004. A prefix operator's operand takes only tighter levels, replacing point 3's "at that operator's level". An operator that must not commit on a missing operand looks ahead for one, replacing point 5's advice to wrap the operator in `Atomic`.

Note: [ADR-0020](0020-depth-counts-rec-bind-and-operands-and-ends-the-parse.md) pins ADR-0004 point 5's "operand recursion" to a prefix operator's operand and an `InfixR` right operand. Other infix right operands do not count, because the table's size bounds their recursion.

Note: [ADR-0021](0021-how-failures-are-recorded-and-merged.md) refines [ADR-0008](0008-control-node-semantics.md) points 4 and 5. `Named` keeps expectations recorded at its start before it ran, counts failures rather than expectations, and never removes a message. A context line applies only to failures past its construct's start, and records where the construct started. It also refines [ADR-0012](0012-custom-scanner-metadata.md) point 4: a `Custom`'s `First` is recorded as one expectation that describes the set, not one per character.

Note: [ADR-0022](0022-a-successful-longest-restores-the-furthest-failure.md) settles [ADR-0017](0017-regular-subtrees-compile-to-an-eager-commit-aware-automaton.md) point 6 for `Longest`. A successful `Longest` restores the furthest failure, so a compiled one records nothing when it matches. This extends [ADR-0021](0021-how-failures-are-recorded-and-merged.md) point 2, under which `Lookahead` and `Not` restore, to `Longest`. Any other kind of compiled subtree needs its own record.

Note: [ADR-0023](0023-token-types-describe-their-kinds.md) moves `Describe(TKind)` from `TokenGrammar`, where the whitepaper first put it, to a static virtual member of `IKinded<TKind>`. It also fills [ADR-0021](0021-how-failures-are-recorded-and-merged.md) point 6: `Kind(k)` displays as `Describe(k)`, and `Case<TCase>()`, missing from that table, displays as the case type's name.
